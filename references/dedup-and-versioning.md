# 去重与版本链

## 1. 去重键优先级

严格按顺序取第一个可用标识符：

1. `doi:<归一化DOI>` —— 去掉 `https://doi.org/`、`doi:` 前缀，统一小写；
2. `arxiv:<编号>` —— 统一小写，去掉 `arxiv:` 前缀与版本后缀；
3. `pmid:<数字>` —— 去掉 `pmid:` / `pubmed` 前缀；
4. `title:<归一化标题>|<年份>` —— 标题做 Unicode NFKC、去标点、转小写、压缩空白。

优先级保证：有 DOI 的同一条记录，不会因为标题写法不同而拆成两条。

## 2. 合并规则

同一 `dedup_key` 的多条记录合并为一个条目：

- 保留全部来源定位（`file` + JSON Pointer / 行号 / XPath）；
- 保留全部标识符（DOI、PMID、arXiv 并列）；
- 标题取信息量最大的版本，日期取最晚的索引日期；
- 标记为一条 `duplicate_group`，提醒中只出现一次。

## 3. 版本链

预印本、正式发表版、修订版可能标识符不同，用以下信号连成一条链：

- 记录中的 `relation` / `related_identifiers` 显式指向另一实体（`is-preprint-of`、`is-version-of`、`updates` 等）；
- 归一化标题高度相似、作者有交集、年份兼容；
- 记录自带 `version` 字段且高于链上已有版本。

链上合并后：

- 发布状态取最"正式"的一版（formal > preprint）；
- 所有定位都保留，不丢弃预印本来源；
- 版本号更高或带修订标记时，分类为 `updates`，而不是 `new_items`；
- 链上任一条带撤稿标记，分类为 `retractions`，优先级最高。

## 4. 不得做的事

- 不因为标题相似就直接合并：必须有标识符或作者/年份支持。
- 不把撤稿声明合并进被撤稿论文本身：撤稿声明是独立实体，单独进入 `retractions`。
- 不静默丢弃重复记录：重复组写入 `duplicates` 并保留定位。
- 不把版本更新当作新论文重复提醒：同一实体只保留一条提醒。
